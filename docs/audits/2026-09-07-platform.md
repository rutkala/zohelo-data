## Goal coverage and open decisions

- **NBP source coverage:** all four configured source IDs have state, source metadata, and model metadata. The targeted probe validates representative ranges only; gaps, recheck latency, and old missing legacy history remain unresolved.
- **Metrics:** the catalogue deliberately has no business metrics. Metric use cases, definitions, dimensions, time aggregation, and approval remain owner decisions; the synthetic native MetricFlow fixture must not be presented as production coverage.
- **New sources:** no source expansion is approved. Commercial reuse, attribution, and licensing evidence must be reviewed before onboarding another source; public HTTP access alone is insufficient.
- **UI:** catalogue discovery is implemented alongside SQL; a redesigned portal and served backend remain deferred.

## Cost, risk, and release status

The runner bounds one invocation to 2,048 observation batches total across the four sources plus catch-up, 512 requests, 256 MiB working raw data, 12 MB per response, and 45 minutes of intake. The state/raw inventory can grow by roughly eight observation batches per day; long-term growth requires compaction before these bounds are reached. GitHub documents standard Actions runner minutes as free for public repositories in its [product billing guidance](https://docs.github.com/en/billing/concepts/product-billing/github-actions). Drive service limits are documented in the [Drive API quota policy](https://developers.google.com/workspace/drive/api/guides/limits). Account-specific quotas and billing were not inspected, and no free-unlimited promise is made. Actual runner usage, peak RAM, and query p95 still require live proof; existing 5 TB storage does not provide unlimited compute.

The current live release remains v1 silver. PR57 is merged, but the bootstrap is in progress and no v2 live status is claimed until final coverage and publication evidence are explicitly confirmed. Business metric approval, new-source commercial licensing, and served-backend availability remain open.

## Bounded ingestion efficiency follow-up

The first bootstrap showed roughly 15 seconds between saved state snapshots. Code inspection found five repeated Drive operations immediately after each already-verified commit. The follow-up returns the exact verified pointer bytes and reuses the committed state in process. Every subsequent commit still reads the live pointer and checks for drift; immutable snapshot and pointer readback, ancestry checks, and size/hash checks remain. The 13 state tests and three runner tests passed locally, including reuse followed by competing-pointer rejection. CI and a measured live comparison remain pending.
